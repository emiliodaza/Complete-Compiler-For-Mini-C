# MiniC Compiler

[![Build and test](https://github.com/emiliodaza/Complete-Compiler-For-Mini-C/actions/workflows/ci.yml/badge.svg)](https://github.com/emiliodaza/Complete-Compiler-For-Mini-C/actions/workflows/ci.yml)

A compiler written in **C++** for a small integer-based subset of C. It uses
**Flex and Bison** to build an abstract syntax tree, lowers that tree to **LLVM
IR**, applies custom optimizations, allocates registers, and emits **32-bit x86
Linux assembly** through a handwritten backend.

The compiler implements its own optimization passes, register allocation, and
assembly generation. LLVM supplies the IR representation, construction API, and
verifier; the final assembly is generated by this project's backend.

## Compiler pipeline

```text
MiniC source (.c)
    → Flex lexer / Bison parser
    → AST and semantic analysis
    → LLVM IR construction and verification
    → Custom local and global optimizations
    → Register allocation and spilling
    → i386 Linux assembly (.s)
```

| Stage | Implementation |
| --- | --- |
| Frontend | Expression precedence, nested blocks, symbol scopes, declaration checks, and call validation |
| IR generation | Integer operations, basic blocks, conditional branches, loops, and a shared return block |
| Optimization | Common subexpression elimination, constant folding, reaching-definition-based constant propagation, and iterative dead code elimination |
| Register allocation | Basic-block live intervals, register reuse, and spilling to stack slots |
| Backend | AT&T syntax assembly, signed division and comparisons, runtime calls, and Linux i386 calling conventions |
| Validation | LLVM verification before and after optimization; execution tests against Clang |

## Build and try it

The compiler builds on **Linux or macOS**. Its generated assembly always targets
**i386 Linux ELF / System V ABI**, including when the compiler runs on a Mac.

Install build dependencies on Ubuntu / Debian:

```sh
sudo apt-get update
sudo apt-get install build-essential clang llvm-dev bison flex gcc-multilib python3-venv
```

Or on macOS with Homebrew:

```sh
brew install llvm bison python
```

Then clone, build, and run the included factorial example:

```sh
git clone https://github.com/emiliodaza/Complete-Compiler-For-Mini-C.git
cd Complete-Compiler-For-Mini-C
make -j4
python3 -m venv .venv
.venv/bin/python -m pip install -r tests/requirements.txt
make demo
```

Expected output for factorial of 6:

```text
720
return=720
```

`720` is printed by the compiled program; `return=720` reports its full signed
return value on stderr. The demo assembles and executes the generated i386
instructions using Unicorn, so it also works on ARM64 Macs. Only the `read` and
`print` runtime functions are simulated.

Dependencies are a C++17 compiler, LLVM development libraries with `llvm-config`,
Bison 3+, and Flex. The Makefile detects Homebrew LLVM and Bison. For another
installation, use `make LLVM_CONFIG=llvm-config-18 BISON=/path/to/bison`.
`CXX=clang++`, `CLANG=/path/to/clang`, and `PYTHON=/path/to/python` can be supplied
for the build and test tools.

## Example program

[`examples/factorial.c`](examples/factorial.c):

```c
extern void print(int);
extern int read();

int factorial(int n) {
    int result;
    result = 1;
    while (n > 1) {
        result = result * n;
        n = n - 1;
    }
    print(result);
    return result;
}
```

Run a different argument or supply input for `read()`:

```sh
.venv/bin/python tools/run.py examples/factorial.c 5
# stdout: 120; stderr: return=120

.venv/bin/python tools/run.py examples/read_and_compute.c --input 20 3
# stdout, one value per line: 23, 17, 60, 6; stderr: return=23
```

## Run the generated binary directly on Linux

With the 32-bit development libraries installed (`gcc-multilib` on Ubuntu):

```sh
./minic examples/factorial.c
cc -m32 -no-pie examples/factorial.s runtime.c -o build/factorial
./build/factorial 6
```

Or test standard input:

```sh
./minic examples/read_and_compute.c
cc -m32 -no-pie examples/read_and_compute.s runtime.c -o build/read_and_compute
printf '20\n3\n' | ./build/read_and_compute
```

`./minic path/to/program.c` writes `path/to/program.s`. The single source
function is exported as `main_function`, regardless of its source name.
[`runtime.c`](runtime.c) supplies `main`, `read`, and `print`. Its optional
command-line integer supplies the function parameter; functions without a
parameter can use the same runtime. The runtime reports the return value on
stderr and exits with status zero after successful execution.

## Tests and continuous integration

After installing `tests/requirements.txt`:

```sh
make test          # i386 machine-code emulation; Linux or macOS
make test-native   # emulation AND actual 32-bit binaries; x86 Linux with multilib
```

The suite compiles each valid test program independently with MiniC and Clang,
then compares printed output and full signed return values. It includes focused
regressions and **100 reproducible random expression programs**. The emulator
also checks stack alignment, stack restoration, and callee-saved registers, and
clobbers caller-saved registers and flags during runtime calls.

Coverage includes arithmetic and signed division; all six comparisons;
expression precedence; constant propagation; branches and nested loops; early
returns; shadowing; input/output; and register pressure. Invalid programs must
produce diagnostics and nonzero exit codes.

The default suite contains **141 programs, 966 executions, and 23 expected
rejections**. `make test-native` additionally executes the same 966 cases as
linked Linux binaries. The [GitHub Actions workflow](.github/workflows/ci.yml)
builds on Ubuntu 24.04, runs both forms of execution, and checks the documented
input/output example. Development was also tested locally on ARM64 macOS with
LLVM 21.1.8, Bison 3.8.2, Flex 2.6.4, and Apple Clang.

## Language scope

Each source file starts with these declarations, in this order:

```c
extern void print(int);
extern int read();
```

They are followed by **one `int` function**, taking either no parameters (`()`)
or one `int` parameter.

Supported constructs:

- Local `int` declarations, assignments, and nested blocks with shadowing.
- `if` / `else`, `while`, `return expression;`, and expression statements.
- Signed integer arithmetic: `+`, `-`, `*`, `/`, and unary `-`.
- Comparisons: `<`, `<=`, `>`, `>=`, `==`, and `!=`, yielding integer 0 or 1.
- Nonzero integer conditions, `read()`, and `print(expression)`.
- Line comments, block comments, and CRLF line endings.

This project implements a MiniC subset. Multiple user functions, user-function
calls and recursion, `void` function definitions, arrays, pointers, globals,
declaration initializers (`int x = 1;`), `for`, `break`, `%`, and logical operators
are outside its scope. `print` has no return value and cannot be used as an
integer expression. A function that falls through returns zero.

Integer literal tokens are decimal and must fit `0..2147483647`; the minimum
signed integer can be written as `-2147483647 - 1`. Programs should initialize
variables before use and keep arithmetic within the signed 32-bit range.
Known constant division by zero and signed division overflow are diagnosed
during IR construction, including in unreachable source branches. Runtime
division errors and reads of uninitialized variables are not checked statically.

## Source map

| File | Responsibility |
| --- | --- |
| [`parser_and_analyzer.l`](parser_and_analyzer.l) | Lexical rules |
| [`parser_and_analyzer.y`](parser_and_analyzer.y) | Grammar and semantic analysis |
| [`ast.h`](ast.h), [`ast.c`](ast.c) | AST types, constructors, and cleanup; compiled as C++ |
| [`IR_Builder.cpp`](IR_Builder.cpp) | Scope-aware renaming and LLVM IR construction |
| [`local_and_global.cpp`](local_and_global.cpp) | Custom optimization passes |
| [`assembly_code_generator.cpp`](assembly_code_generator.cpp) | Liveness, allocation, spilling, and i386 emission |
| [`main_function.cpp`](main_function.cpp) | Compiler driver and verification |
| [`runtime.c`](runtime.c) | Native program entry point and integer I/O |
| [`tools/run.py`](tools/run.py) | ELF loading, relocations, and emulated execution |
| [`tests/test_compiler.py`](tests/test_compiler.py) | Differential, runtime ABI, and rejection tests |

The root-level LLVM header snapshots are historical reference material. They
retain their upstream license notices and are excluded from GitHub language
statistics; the build uses the installed LLVM headers and libraries.
